# 架构与关键选择

集刻把同一套活动界面接到不同的数据通道。它们共用交互组件，但认证与数据边界不同。

| 模式 | 入口 | 数据通道 | 身份与持久化 |
| --- | --- | --- | --- |
| 公开展示 | `/demo/` | `src/lib/showcase.ts` | 虚构身份，页面内存；刷新重置 |
| 本机演示 | `/`，默认模式 | Next.js API → `service.ts` → PGlite | 可切换预设身份；`.data/campus` 持久化 |
| 本机账号 | 3011 端口 | Next.js API → 会话校验 → PGlite | 独立账号；`.data/accounts` |
| CloudBase | `/campus/` | SDK 认证 → PostgREST → `cg_call` → PostgreSQL | 平台会话；服务端角色、所有权和 RLS |

## 从操作到数据

`src/components/campus.tsx` 调用选定的数据通道。展示模式即使有云端配置，也不会选中真实通道；其演示模型没有网络和持久化调用。它不是权限证明。

本机 `src/app/api/activities/route.ts` 从服务器取得当前用户，调用业务服务。账号模式忽略 `x-demo-user`，只有演示模式允许白名单身份选择。账号密码使用 scrypt 与独立盐；随机会话仅以摘要存入库，浏览器使用 HttpOnly/SameSite Cookie，HTTPS 时附加 Secure。跨来源写请求被拒绝。

云端浏览器只配置公开环境 ID，认证由 CloudBase SDK 处理。数据库的 `cg_call` 为 SECURITY DEFINER 函数，固定空 search_path；自行检查平台账号是否存在、所有者、截止时间、容量与发布限额。应用角色不能直接写三张表。RLS 限制自己的资料与报名，活动可由已认证账号读取；名单只能由该活动发布者经 RPC 获得。客户端传入的角色或其他用户 ID 不能代替服务端身份。

## 数据模型

| 表 | 关键字段与约束 |
| --- | --- |
| `cg_profiles` | `id`、昵称、student/organizer；历史角色字段保留；有效账号均可发布 |
| `cg_activities` | 所有者、日期、截止、容量 1–500；截止不晚于开始 |
| `cg_registrations` | 活动/用户联合主键、registered/cancelled、首次签到时间 |

## 一致性

云端所有报名变更遵守“锁活动 → 检查或修改报名”的顺序。活动行锁把最后名额竞争串行化，取消与签到也经过同一锁；取消释放名额，重新报名复用原记录。签到用 `coalesce` 保留首次时间，已签到不可取消报名。发布者可取消整场活动并公开原因；历史记录保留，后续报名与签到被拒绝，已有参与者仍可取消未签到报名。本机另有进程内队列，不能把它当作分布式锁。

独立 PostgreSQL 连接的最后名额、重复提交、取消及签到竞争已有可复现测试，并通过移除锁的负向对照确认能发现超额。见 [并发验证](POSTGRES_CONCURRENCY.md)。它不是云端真实双账号或吞吐测试。

## 当前取舍

- 静态展示可免账号体验；本机模式无需云服务；真实共享数据才需要自建 CloudBase 环境。
- 名单导出只包含当前筛选结果，防护表格公式注入；失败刷新时隐藏旧数据并禁用导出。
- 活动封面用 CSS 绘制，无外部字体、图片和付费 AI API。
- 当前活动列表最多 100 项，未实现分页、签到时段及现场核验。注册用户自助发布，无需角色审核；每账号滚动 24 小时最多发起 5 场，锁住用户资料行后计算，取消也计入限额。
- 本机限流仅在进程内，没有完整找回密码、注销及邮箱所有权验证；应限于开发演示。
- 云端平台身份适配依赖 `auth.uid()` 与 `auth.users.sub`；不能直接把迁移当作任意 PostgreSQL 的通用账号方案。
