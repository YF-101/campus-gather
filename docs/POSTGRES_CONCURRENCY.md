# PostgreSQL 独立连接并发验收

2026-11-08，`npm run test:postgres` 完整六项通过，退出码 0。

## 环境与方法

本机 Docker 官方 `postgres:16-alpine` 镜像，实际版本 PostgreSQL 16.15 / aarch64。镜像摘要：`sha256:aa6cb33cf4c19c765cefcf48d96176258800870a9a1e930ad126200f9d825139`。

脚本：[tests/postgres-concurrency.mjs](../tests/postgres-concurrency.mjs)。不增加应用依赖，使用容器内 psql；不发布主机端口、不挂载主机目录、禁用外部网络。临时库创建虚构用户并运行现有三份校园迁移，不使用云端凭证或连接腾讯云。正常完成和异常退出路径均尝试删除自己创建的容器及匿名卷；强制终止进程或 Docker 故障时可能需检查 `campus-pg-test-` 前缀遗留容器。

第三个连接锁住活动行，两个业务连接提交请求。通过 `pg_stat_activity` 确认实际发生数据库锁等待后才放行，不仅是同时启动两个 JavaScript 函数。业务调用使用 authenticated 角色和虚构身份声明；不代表完成平台登录验证。

## 六项结果

| 场景 | 实测结果 |
| --- | --- |
| 两名学生抢最后名额 | 一个成功，另一个“名额已满”，活跃报名数 1 |
| 取消后重新争抢 | 取消后为 0；两人重新竞争仍仅一个成功，最终为 1 |
| 同一学生重复提交 | 一个成功，另一个“已经报名”，仅一条活跃报名 |
| 签到先提交、取消等待 | 取消被拒绝，签到保留；重复签到不改首次时间 |
| 取消先提交、签到等待 | 签到被拒绝，取消记录未被错误签到，活跃报名数 0 |
| 负向对照 | 临时克隆 RPC，移除活动行锁，在读取名额后同步两连接：两人均成功、名额变成 2，原单名额断言正确失败 |

负向对照的断言失败被测试明确捕捉；整体测试通过表示它检测到了故意注入的缺陷。没有修改生产迁移或云端函数。

首次运行遇到镜像初始化临时 Unix socket 服务就绪后重启，测试连接随即失败。已将就绪探测与测试连接统一为容器内部 TCP，等待最终服务；属于测试脚本启动问题，不是报名业务缺陷。修正后完整六项通过。

## 复现

```sh
docker pull postgres:16-alpine
npm run test:postgres
```

可用 `CAMPUS_TEST_POSTGRES_IMAGE` 指定兼容镜像或固定摘要，无需 API 密钥、密码或验证码。

## 证据边界

这补充了当前迁移在本机真实 PostgreSQL、默认 READ COMMITTED 下的多连接证据，超出 PGlite 单连接测试范围。但不能替代腾讯云网关、真实认证及双浏览器联合验收；未测吞吐、延迟、其他事务隔离级别、长期负载和灾难恢复。
