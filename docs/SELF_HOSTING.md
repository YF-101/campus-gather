# 自己运行与部署

不需要购买服务器才能看代码或体验演示。默认本机模式无需云服务；真实多人共享数据才需要自己的后端环境。

## 1. 本机运行

使用 Node.js 22.18+（22.x）与 npm：

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:3010/demo/` 体验刷新重置的虚构数据，或 `/` 体验本机数据库。数据库在 `.data/campus`，不会同步给别人的电脑。

独立账号模式先 `npm run build`，再 `npm run start:accounts`，访问 `http://127.0.0.1:3011/auth`。新用户只能注册为学生，本机演示身份不授予真实账号组织者权限。数据位于 `.data/accounts`。不要将该本机账号版直接开放公网，它还缺少完整账号生命周期和多实例防滥用。

## 2. 准备自己的 CloudBase 环境

项目目前适配 CloudBase SDK 认证、PostgreSQL/PostgREST 与静态网站托管。自行创建环境前，先在平台控制台确认地区、免费额度、有效期和费用选项；仓库不替你注册、购买或开通按量付费。

后端依赖平台提供 `auth.uid()`、`auth.users.sub` 以及 `anon`/`authenticated` 角色。先在空白开发环境确认这些接口匹配，再初始化；普通 PostgreSQL 不能只执行迁移就自动获得平台认证。

按顺序执行 `cloudbase/migrations/` 三个文件：

1. `202611080001_campus.sql`：业务表、RLS、受保护 RPC 和明确标记的虚构初始活动。
2. `202611080002_email_status.sql`：只读查询当前邮箱验证状态；当前普通校园报名不依赖它。
3. `202611080003_account_enrollment.sql`：将普通报名条件设为有效学生账号，不额外要求邮箱验证；其他权限检查保持不变。

这些是一次性迁移，不是可重复运行的初始化按钮。不要在已有业务表的生产库盲目重跑。`verify-organizer-rollback.sql` 是审计用途的回滚脚本，不是日常业务迁移。

在平台开启项目所需的用户名/密码与邮箱验证码注册登录，配置自己的发件服务和允许访问域名。不同平台套餐或版本可用能力可能不同；发出验证码不等于验证完成，需完整验收注册和登录。不要在仓库、Issue 或聊天中分享密码、验证码和服务端密钥。

## 3. 构建和托管

公开环境 ID 不是服务端密钥。构建只需要：

```sh
NEXT_PUBLIC_CAMPUS_CLOUDBASE_ENV_ID=你的公开环境ID npm run build:cloud
npm run check:artifact
```

脚本临时切换云端页面并移开本机 API，构建后恢复源码。生成 `out/`，所有资源以 `/campus/` 为前缀；把 **out 内的内容** 上传到托管站点的 **campus 目录**，不是上传整个工程。不要覆盖同站点已有的根目录网站。

页面源码的免费测试有效期和共用账号文案是原展示环境说明。部署自己的环境前，在 `src/components/cloud-auth-form.tsx` 中改为自己的真实说明；README 在线演示地址也应按需替换。不要承诺未经确认的免费期限。

这个静态包不能调用本机 Next.js API。线上只能使用配置正确的 CloudBase 通道；不要把本机模拟身份头当作身份认证。构建静态版后，如需再启动本机生产服务，先重新 `npm run build`。

## 4. 组织者与上线前验证

真实账号首次进入会创建默认学生资料。组织者需部署者在后台核对账号并授权，没有公开自助升权入口。修改的是校园资料角色，不应更改平台账号或其他应用权限；当前组织者不能以普通学生身份报名，联动验收需另一学生账号。

至少检查：匿名拒绝、学生无法发布/读取名单、组织者不能管理他人活动、两个独立账号发布到签到闭环，以及实际手机与不同网络。自动化命令及当前验证范围见 [测试说明](TESTING.md)。

GitHub 保存源码，不代替数据库、认证和托管。部署者退出云控制台通常不影响正在运行的服务；环境停用、额度耗尽或配置失效会影响服务。请以自己控制台的实际状态为准。
