# 如何介绍这个项目

先运行项目，能够复现并解释关键行为，再用于简历或面试。不要将 AI 辅助完成的内容描述成全部独立手写，也不要声称已支撑大量真实用户。

## 一分钟介绍

可以围绕三个事实组织自己的表达：这是学生与组织者两种角色的活动报名系统；除界面外，服务端限制操作权限并处理名额与状态竞争；提供免登录演示和可复现测试，同时公开尚未完成的真实账号与负载验收。

## 建议现场演示

1. 用公开演示切换角色，展示报名、名单、签到和导出；说明虚构数据刷新重置。
2. 打开 `cg_call` 的活动行锁和服务端身份检查，解释为什么前端禁用按钮不够。
3. 运行 `npm run test:postgres`，解释一个名额为何只成功一人，以及移除锁的负向对照为何会超额。
4. 指出本机演示、账号模式、云端和纯内存展示的差别，说明哪些已验证、哪些还没验证。

## 应能亲自回答

- 联合主键能防重复报名，为什么仍需要活动行锁？
- 已签到后不能取消，在两个请求竞争时如何保持规则？
- SECURITY DEFINER 函数为什么还要检查身份、所有者并固定 search_path？
- PGlite 单连接、真实 PostgreSQL 多连接和云端双账号测试分别证明什么？
- Cookie 为什么要 HttpOnly/SameSite，为什么账号模式不能接受模拟身份头？
- CSV 为什么需要转义及公式前缀防护？
- 哪些内容由你提出或验证，哪些由 AI 辅助实现？下一次准备自己改哪一部分？

## 建议的下一次独立练习

从一个小问题开始：给活动列表增加分页，先写行为预期与失败场景，自己完成修改并展示测试结果。理解后再继续账号审核或签到时段；不需要为了项目数量反复创建相同 CRUD 页面。
